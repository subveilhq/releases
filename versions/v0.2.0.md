# Subveil v0.2.0

Subveil v0.2.0 adds native MySQL and MariaDB support alongside PostgreSQL. The CLI can introspect a MySQL-compatible schema, plan a foreign-key-connected subset, mask values while reading source rows, and load the result into a separate target database.

## What's new

- **MySQL and MariaDB engine support.** Set `engine: mysql` in `subveil.yaml`. MySQL accepts `mysql://` URLs or Go driver DSNs. MariaDB uses the MySQL engine.
- **Consistent, read-only source reads.** MySQL source reads use a consistent snapshot (`START TRANSACTION WITH CONSISTENT SNAPSHOT`); the source is never written to.
- **Native schema creation for MySQL.** `--create-schema` builds the target tables with `SHOW CREATE TABLE`, so no external `mysqldump` is needed.
- **MySQL-aware loading.** Batched multi-row `INSERT`s (up to 250 rows or 8 MiB per batch), `AUTO_INCREMENT` counters reset after the load, generated (`VIRTUAL`/`STORED`) columns skipped, and circular and self-referential foreign keys handled by disabling `FOREIGN_KEY_CHECKS` for the loading session only.
- **JSON document masking.** Apply JSONPath rules to PostgreSQL `json`/`jsonb` and MySQL `JSON` values with the `jsonb` transformer.
- **More deterministic transformers.** `token`, `number`, `date_shift` and `ip` for sensitive identifiers, numbers, dates and IP addresses. `ip` is chosen automatically for PostgreSQL `inet` and `cidr` columns.
- **Failed pulls are recorded.** A failed cloud-mode pull now records an audit receipt, so failures show up in the audit log.

## Upgrading from 0.1.x

The database engine is now an explicit setting. Add `engine: postgres` (or `engine: mysql`) at the top of your existing `subveil.yaml`:

```yaml
version: 1
engine: postgres
```

`init`, `plan` and `pull` ask you to choose when the key is missing, but only on a terminal. In CI, without the key, they stop with exit code 2. The engine is never guessed from the connection string.

## Tested database versions

The database-backed integration suite was run locally against PostgreSQL 16, MySQL 8.0, MySQL 8.4 and MariaDB 10.6. CI is configured to run it on those versions. This does not verify managed-provider configurations or every server version.

## Known issues

- **MySQL schema creation is not rolled back.** MySQL schema DDL commits implicitly. If a pull fails after `--create-schema` or `--recreate-schema`, the row load is rolled back but the schema changes are not. Use a dedicated, empty target database.
- **The built-in API address does not resolve.** The CLI's default control-plane address in this version is wrong, so `subveil login` fails unless you set `SUBVEIL_API_URL=https://subveil.dev` (or pass `--api-url https://subveil.dev`). Fixed in v0.2.2.

## Security and data handling

The CLI runs in your infrastructure. Source reads are read-only; raw row values are masked in process and are not sent to Subveil Cloud. Cloud features exchange metadata and audit receipts only. An audit receipt can support evidence collection, but does not itself establish SOC 2, HIPAA, or other compliance.
