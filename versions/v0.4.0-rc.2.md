# Subveil v0.4.0-rc.2

## Changes

- Simplify local workflows around `init`, `plan`, `pull` and `verify`. Sensitive-column discovery is included in `plan`; the standalone `scan` and `doctor` commands are removed.
- Rename subset `default_scale` to `default_sample_rate`. YAML and API values are positive fractions up to 1; existing configs must rename the key while keeping the same value.
- Keep `pull` local-first: it uses masking rules in `subveil.yaml` and never downloads Cloud policy implicitly. Linked Cloud reporting is best effort; `--no-cloud` disables it, while `--require-audit` requires receipt acceptance and can fail after the database copy has completed.
- Add `schema push` for metadata-only schema reporting, and `policy push` for reviewing and publishing local policy fields. `policy pull` remains the explicit operation for downloading the published policy.
- Improve Cloud project linking with interactive project selection and save signed pull receipts locally before attempting Cloud delivery.
- Retain `branch report` and `ci report` for workflow automation while keeping them out of the primary root help listing.
- Use `https://subveil.dev` as the default Cloud API endpoint. Cloud URLs and masking keys use `SUBVEIL_SOURCE_URL`, `SUBVEIL_TARGET_URL` and `SUBVEIL_MASK_KEY`.

## Validation limitations

- This release candidate has not yet been tested in GitHub Actions using its published release assets and a live Cloud project.
- MySQL/MariaDB live database tests and Docker multi-architecture builds were not available in the local validation environment; Go cross-compilation and temporary macOS/Linux archive checksum checks passed.
