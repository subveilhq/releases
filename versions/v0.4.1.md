# Subveil v0.4.1

## Verification

- `verify` samples near the beginning, numeric midpoint, and end of single integer primary-key ranges. This can catch sensitive values beyond the first rows. Composite and UUID primary keys use beginning and end windows, and keyless tables use a bounded scan.
- The one-minute sampling budget now applies to active database reads. Reports show how many values were examined per column and identify columns that were skipped or left unexamined. Terminal summaries distinguish incomplete checks and warnings from a full pass.
- Sampling examines up to 100 rows per candidate column. Sparse keys can cause windows to overlap, leaving fewer distinct values to examine. Sampling cannot establish that all sensitive values were removed.

## PostgreSQL

- Pull now restarts descending sequences and identity columns in the correct direction. Restart calculations use the sequence's configured increment, start, and bounds.
- If no restart value remains within the bounds beyond the copied identifiers, pull reports the affected sequence and fails. Sequence restarts still roll back with the default transactional load.

## Compatibility

- In `verify --json`, `sampling.method` changes from `first_n_non_null` to `primary_key_windows_or_bounded_scan`. Use the new value if automation matches it explicitly. The report adds `column_samples` with examined counts. Eligible totals and coverage percentages are unknown and reported as `null`.
- Verification exit codes are unchanged. Use `--strict` to fail on warnings or skipped checks. No CLI commands or flags were added.
- PostgreSQL target schema creation and recreation still require a compatible `pg_dump`.
