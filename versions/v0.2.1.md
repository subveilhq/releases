# Subveil v0.2.1 — Draft release notes

Subveil v0.2.1 hardens how the CLI talks to the Subveil control plane. Masking, subsetting and loading are unchanged.

## What changed

- **The control-plane URL must use https.** The CLI now refuses to send your API key or any receipt to a plain `http://` URL. `http://localhost`, `http://127.0.0.1` and `http://[::1]` are still accepted, so local development servers keep working. A URL that contains a user name or password is refused. If you set `--api-url`, `SUBVEIL_API_URL` or saved credentials to an `http://` address on another host, switch it to `https://`.
- **Redirects stay on the same origin.** An API call follows at most three redirects, and only to the same scheme and host, so a redirect can no longer downgrade a connection to http or carry your API key to another host.
- **`subveil login` checks the browser link.** The login link the server returns must be on the same host as the API you chose, otherwise the login stops and nothing is opened. The confirmation code is printed with control characters removed.

## Upgrading

No configuration change is needed when you use the default service. If `subveil login` or a cloud-mode `pull` now fails with "API URL must use https", correct the URL.

## Security and data handling

The CLI runs in your infrastructure. Source reads are read-only; raw row values are masked in process and are not sent to Subveil Cloud. Cloud features exchange metadata and audit receipts only.
