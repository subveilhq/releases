# Subveil v0.4.0

## Local database workflow

- Use `init` to create local configuration, `plan` to inspect dependencies and candidate sensitive columns, `pull` to copy and mask rows, and `verify` to check the target.
- `plan` includes sensitive-column discovery. The standalone `scan` and `doctor` commands have been removed. Unknown `verify --checks` names exit with code 2.
- Rename the YAML key `subset.default_scale` to `subset.default_sample_rate`, keeping the fraction unchanged. New configurations use `SUBVEIL_SOURCE_URL`, `SUBVEIL_TARGET_URL`, and `SUBVEIL_MASK_KEY`.

## Cloud and CI

- Pull uses local YAML. Use `schema push` to report database structure and `policy pull` or `policy push` to synchronize policy explicitly.
- Successful non-dry-run pulls save authenticated receipts locally. Linked Cloud reporting is best effort. `--no-cloud` disables Cloud requests. `--require-audit` requires Cloud receipt acceptance and can fail after the database copy completes. Offline receipts stay local when the CLI reconnects.
- GitHub Actions workflows can report database preparation, job outcome, and PR closure. A ready database can still be followed by a failed job. The workflow reports the outcome separately from database readiness and PR closure.

## PostgreSQL

- PostgreSQL 18.6 validation covered composite keys, foreign keys, partitioned tables, enums, domains, stored generated columns, and views.
- Sequence restarts roll back with the default transactional load. The target role must be able to alter sequences used by copied columns.
- Virtual generated columns and foreign-table data are outside the copy scope. Refresh materialized views on the target before querying them.
